📌 1. Project Summary (The 30-Second Elevator Pitch)

SupportX is a production-ready enterprise customer service platform designed to automate ticket lifecycle management, prevent breached service level agreements (SLAs), balance engineering workloads, and bridge communication between customers and technical support agents in real time.

🚨 The Problem
Unmanaged ticket backlogs, missed SLA deadlines, overloaded support agents, and sensitive internal diagnostic notes accidentally leaking to customers.
💡 The Solution (SupportX)
Dynamic SLA calculation engine, automated workload-based dispatching, finite state machine lifecycle guard, strict staff note isolation, and real-time WebSockets.

🔑 3. Core Functional Modules (How It Works)

⚡ Dynamic SLA Engine: When a customer submits a ticket, the system matches its Category (Software, Hardware, Network, Billing) and Priority (Urgent, High, Medium, Low) against the database SLA matrix to automatically compute the exact resolution due date. (e.g., Urgent Software = 4 Hours Guaranteed Resolution).
🔒 Staff Privacy Isolation (Module 8): Support agents can flag internal comments as "Private Internal Notes". The database query automatically strips these notes when a customer fetches comments, preventing internal technical discussions from being exposed.
Module Feature Name How It Works In Simple Terms
Module 1 Role-Based Access (RBAC) Secures endpoints for 4 discrete roles: customer, agent, manager, admin.
Module 3 Auto-Dispatch Engine Counts active tickets per agent and automatically assigns new tickets to the least loaded engineer.
Module 4 Finite State Machine Strictly enforces status flow: Open ➔ In Progress ➔ On Hold/Resolved ➔ Closed.
Module 6 & 9 Breach Scanner & Escalation Background scanner flags SLA breaches and enables agents to escalate tickets with justification notes.
Module 11 Customer CSAT Rating Resolved tickets allow customers to submit 1–5 star ratings with feedback and confetti effects.
Module 12 & 13 Manager BI Analytics Aggregation pipelines compute SLA Compliance Rate %, Agent Workload, and Category breakdowns.

💡 5. Technical Defense & Viva Q&A Guide

Q1: Why did you choose Angular 18 Standalone Components?
Answer: Standalone components remove legacy NgModule overhead, enable clean dependency injection, reduce initial bundle size to ~426 KB, and integrate natively with TypeScript and RxJS reactive streams.
Q2: How is the SLA deadline calculated?
Answer: The SLA Helper queries the database SlaRule matrix matching category and priority. It adds the configured resolutionHours to Date.now() and stores slaDueAt in the ticket document.
Q3: How do you prevent race conditions when auto-assigning agents?
Answer: The auto-assignment engine runs an aggregation query counting active tickets (Open, In Progress, On Hold) per agent and atomically assigns the ticket to the agent with the minimum active count.
Q4: How does privacy isolation work for internal staff notes?
Answer: At the controller level, if req.user.role === 'customer', MongoDB executes Comment.find({ ticketId, isInternal: false }). Socket.io also broadcasts internal notes exclusively to the role:agent, role:manager, and role:admin rooms.
